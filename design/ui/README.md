## What UI owns

UI defines bounded **visual interface and content expression**: screen composition, visual hierarchy, final scoped UI language/copy, relevant responsive variants, visually expressed interaction states, visual components/styles and permitted assets. A new/material screen design normally needs **inspectable visual proof**, not merely a textual description.

UI does **not** redefine Product success, Domain Roles, business/legal/privacy constraints; accepted UX flows, IA, navigation/web paths or user-facing interaction-state meaning; target-project reusable Design Standard authority; Engineering APIs/security, component implementation or production behavior.

**Hi-Fi describes intended visual specificity, not a required lifecycle phase or Space.** If existing accepted target-project UI and standards are sufficient, a new Hi-Fi mock is not a universal prerequisite for delegated small implementation changes. For genuinely new/material UI decisions, applicable visual/state/responsive evidence should be present or the affected final acceptance remains unverified/blocked.

## Entry and sufficiency

The [13-input UI coverage](definition.md#2-input--13-decision-specific-information-needs) and [UI Input Sufficiency Check](definition.md#3-ui-input-sufficiency-check) decide what accepted information must exist for the actual task. **New/material UX experiences** must provide UX O2 flow diagram and O6 representative Lo-Fi structures by default (or accepted exact-revision equivalents/justified, legitimate exceptions) before UI makes binding decisions that depend on them. Webpage Map & Routes are required for material web navigation.

UI can investigate a bounded visual direction with clearly marked hypotheses. Missing Product/UX/standard decisions block only their affected **binding UI decisions**, not independent authorized exploration.

## Artifact and authority limits

A render, HTML candidate, PNG, screenshot, Figma file or prototype is **review evidence** until the legitimate project owner accepts its exact scope/revision; a polished view is not Product correctness, production readiness, user usability or project-standard promotion. Record actual render/viewport/state inspection or **NOT VISUALLY VERIFIED**; a source file in Git is not proof it has been viewed in a browser. Respect project security, accessibility, licensing, privacy and Human action permissions.

**A3 research boundary:** These reusable [UI output templates](templates/ui-output.id.md) are **authoring aids**, not completed project-specific UI artifacts or approved visual evidence. No UI Space, `design/project-standard/` guidance, project-level design standard or project write authorization is created by this research guidance.
