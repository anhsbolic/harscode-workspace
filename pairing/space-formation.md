# Pairing — Space Composition and Formation Request (Station 5 Research)

> **Status:** EXPERIMENTAL. This is Balad's **project-facing discovery/reporting contract**, **not** Space Formation design guidance or permission to author reusable definitions.
> **Formation owner:** Anhar + ChatGPT under [space-formation/](../space-formation/README.md). First invocation requires separate authorization.
> **Example kickoff:** [End-to-End Space I/O Chain Kickoff Prompt](space-composition-kickoff-prompt.md) — optional short Human prompt, not a required dossier.

## Balad's responsibility

From current effective project authority, show a **provisional end-to-end outcome/I/O dependency chain** through intended verified outcome and Human acceptance. Include meaningful parallel branches/joins, original acceptance authority supplied to assurance, and what remains conditional. A logical outcome node is not automatically a Space or implementation phase.

For each material producer → consumer edge, check **both layers**:

1. **Generic reusable contract:** expected producer output kind/format/conformance/evidence versus consumer input requirements.
2. **Concrete assignment binding:** the current project's actual requirements, versions, access/scope and required content versus the downstream consumer's needs.

State candidate fit, mismatch or unknown truthfully. A proposed diagram does not prove actual output or consumer acceptance. Validate actual existing Space definition sources before claiming reuse; a guidance file or empty `harscode-state` directory is not a formed Space.

Map each capability need as **reuse / adapt / form / conditional / unresolved** with evidence. Do not hardcode a universal Solution → Build → Assurance pipeline, fix Space count upfront, or force one graph node per Space.

## When no suitable Space is found

Submit a **Formation Request** to Anhar + ChatGPT, not a formed definition. A compact graph/table is enough:

| Report | Supply |
| --- | --- |
| Current goal and owning authority | Project, branch/revision, approved commitment/acceptance and applicable constraints |
| Missing capability | Reusable generic production responsibility; **expected generic IN → OUT**, including required output evidence |
| Concrete binding | What this project's assignment would supply and require from that generic capability |
| Handoff gap | Missing/incompatible producer OUT → consumer IN; generic and project-bound compatibility status |
| Reuse discovery | Checked actual definition locations; existing fit/mismatch, inaccessible sources/unknowns |
| Material limits | Security/permission, output acceptance and downstream assurance needs; conditional design choices |
| Next Human decision | Whether to review a new/adapted capability formation in a separate Anhar + ChatGPT session |

The report may propose a **first candidate**, but must not specify a definitive Agent roster, select protected model/effort options, create profiles, write Space files, dispatch Specialists or claim formation. Later Space-generated improvement requests are likewise routed back to the Human-led reusable formation process; they do not autonomously update contracts.

## Reporting style

Lead with a **short verdict**. For substantive composition, usually present (a) a compact whole-chain diagram, (b) a generic I/O + project-binding + reuse map and (c) material edge compatibility/gaps plus the next formation request. Skip irrelevant detail and don't repeat C1 requirements as an engineering design dossier. Explain uncertainty and stop at the authorization boundary.

Project-specific implementation choices belong to the authorized producing Space/assignment. Balad's chain remains provisional until actual consumers receive and check real outputs.
