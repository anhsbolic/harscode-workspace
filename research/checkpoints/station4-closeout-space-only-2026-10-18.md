## 2. Approved conceptual pilot candidate

**Space-only execution boundary**
- All task-related engineering production/execution is directed through a **Space**. No parallel direct Human–Agent Pairing → Specific Agent execution protocol.
- Space is a reusable, bounded production capability with **strict external input/output contracts** and one coherent production outcome. One or multiple specialized Agents may work and communicate **inside** the Space, with implementation/review/testing as warranted. A small task may use one Agent and minimal external ceremony; complex work may require more capabilities, independently meaningful checks and/or multiple Spaces.
- A Specific Agent Profile describes a bounded capability, specialization, working constraints and internal outputs, bound to appropriate LLM, knowledge, guidance, tools, project authority and assignment at execution. A declared Profile is not proof of actual competence.
- **Space formation is an accepted up-front investment**, potentially reusable across projects, not a per-task requirement to invent a fresh workflow. Formation, scope and project binding are demand/evidence-driven; costs should be evaluated across repeated invocations and project reuse, not solely first-call overhead. Internal execution mechanism, agent count, folder layout and automation are replaceable choices.

**Responsibility and quality ownership**
- **Human + Agent Pairing** owns external communication, upstream content-quality review, version/change coordination between Spaces, risk/outcome-based decision/routing, accepted material outcomes and latest-effective commitment continuity. It **does not** implement/discover/build/test engineering tasks outside a Space.
- **Space is upstream-blind** for substantive review and ambient version monitoring. It checks conformance to its own accepted input contract, operates within own authorization/guardrails, and produces truthful scoped output/evidence. Bad but conformant upstream content is a cross-Space quality failure owned by Human + Agent Pairing, not an automatic requirement for each Space to re-audit upstream.
- Internal Reviewer/Tester assesses **output quality against the Space's accepted input and output obligations**; does not redo upstream design/product decisions. Where binding independent assurance exists, its independence must be real; an implementer cannot silently waive requirements by labeling a self-check independent.
- Risk-based Human intervention or previously authorized delegation, not universal approval ceremonies. A successful Space output is not a claim that the whole project is correct.

**Composition, current state, and ownership**
- Output is offered across a strict contract boundary; Human + Agent Pairing chooses/authorizes the next Space according to valid downstream prerequisites. No mandatory global phase chain, orchestration engine, Run registry, or direct-Agent parallel state protocol.
- Working candidate sibling layout: `/harscode-workspace` for reusable definitions, `/harscode-state` for Harscode operational continuity, `/repo-project` for project authority/code/accepted specifications and owning evidence. Layout is **not** an implemented or universal physical requirement.
- Operational continuity has two logical levels: **Human–Agent Pairing current-effective commitment snapshot** and **concrete active Space execution working state**. Fresh session reads latest **valid** effective state, not historical replay; relevant owning project evidence is opened only as needed. Routine session/run history and duplicate projections are not mandatory. Material approvals, authoritative project decisions, security/verification evidence and relevant provenance remain in owning sources when their consequence requires it.
- For an initial pilot, assume local operational state is available. Lost state may be reconstructed from surviving authoritative/evidence sources or explicitly redefined by Human + Agent Pairing; no fabricated permission, test PASS or prior approval. Backup/remote recovery/storage-engine implementation is deferred unless pilot evidence warrants it.

## 4. Station 5 pilot hypothesis and falsifiers

- **Small scoped outcome:** one-Agent Space invocation maintains strict contract/state/communications without a separate direct Agent route or disproportionate per-use ceremony. Failure: first/repeated invocations remain needlessly expensive or require dual protocols.
- **Complex scoped outcome:** multi-Agent/multi-Space collaboration supports true independent assurance, preserves project-owned authority and avoids context/bias/review-overlap failures. Failure: internal independence is nominal or Agent/Space borders impede correctness.
- **Reuse economics:** Space/Profile formation cost can be amortized over recurring tasks and ideally cross-project use; a project bind does not smuggle target-project truth into reusable definitions. Failure: blueprints remain project-specific or require repeated re-engineering.
- **Durable continuity:** latest valid pairing snapshot + active Space working state enables fresh-session continuation without consuming full Run history; missing evidence is truthfully reported. Failure: unexplained state, hidden conversational dependency or excessive synchronization.
- **Risk/cost outcomes:** bounded quality ownership and Human authority can be maintained with reasonable coordination overhead. Failure: unsafe escalation, silent lost authorization, non-convergent loops, or lower-quality results despite cheaper process.

Evaluate sufficient task-matched real evidence, not raw Run count. No requirement to run every hypothesis in every pilot.
