# Proposal: Refine Human Digest rules — diagram syntax enforcement, relax rule-ID exclusion, enforce risk severity

> Status: Accepted
> Date: 2026-08-13
> Triggered by: GMRT-51524 techplan regenerated by a different model
> under the new guidance (proposal 0001), reviewed against
> `rules.md` § 7 / `guardrails.md` § 8.
> Target: `rules.md` § 7, `guardrails.md` (new § 9), `guidelines.md`
> (step 7), `README.md` (File Map, Fundamental Rules), new file
> `diagram-guidelines.md`

## Friction Found

The first real-world test of proposal 0001 (Human Digest) surfaced
three gaps when a different model generated a techplan under the new
guidance:

1. **Diagram syntax bug.** The generated Mermaid flowchart used
   single-dash edges (`A -> B`) on three lines instead of the required
   double-dash (`A --> B`). Single-dash edges are invalid Mermaid
   flowchart syntax and fail to render silently — the diagram would
   have shipped broken with nothing in `rules.md`/`guardrails.md`
   catching it. This is a recurring risk for any future digest with a
   diagram, not a one-off — hence structural, not a one-line fix.
2. **Rule-ID exclusion was stricter than useful.** `rules.md` § 7 said
   to exclude rule IDs (R1, R2...) entirely. The generated digest
   included a handful of parenthetical rule-ID references (e.g.
   "boundary `== today` included per PRD re-read (R18)") — on review,
   these read as helpful cross-references for a reader who wants to
   jump to the detail, not as noise. The absolute exclusion was
   over-correcting.
3. **Top Risks included a Medium-severity row.** Section 7's Top Risks
   is supposed to be High-severity only; the generated digest included
   one Medium-severity risk alongside four High ones. Unlike #2, this
   is a straightforward compliance gap, not a sign the rule itself is
   wrong.

## Proposed Change

- **New file `diagram-guidelines.md`**: a Mermaid syntax reference +
  self-check checklist (valid/invalid edge table, common mistakes,
  a mandatory pre-finalize validation step). Added to the protected
  "don't edit directly" file list alongside the other stable guidance
  files.
- **`rules.md` § 7**: relaxed the exclusion from "no rule IDs at all"
  to "no full rule-by-rule tables/walkthroughs; a parenthetical
  cross-reference is fine" (with a rough heuristic: if >1-in-3 lines
  carries a rule-ID, that's drift back into rule-by-rule detail).
  Diagram criteria bullet now points to `diagram-guidelines.md` for
  syntax validation. Top Risks bullet now explicitly says to check the
  Severity column before including a row, with guidance for the
  zero-High-severity edge case.
- **`guardrails.md`**: new § 9, "Diagram Syntax Must Be Validated
  Before Finalizing" — same severity tier as § 5 (Don't Invent
  Technical Facts).
- **`guidelines.md`**: step 7 now explicitly calls out the syntax
  validation sub-step.
- **`README.md`**: File Map and Fundamental Rule 1 updated for the new
  file.

## Rationale

Diagram syntax correctness is mechanical and checkable — there's no
judgment call involved, so it belongs as a hard guardrail with a
dedicated reference doc, the same way the workspace already treats
"don't invent line numbers" as a hard guardrail rather than a
suggestion. Rule-ID exclusion, by contrast, turned out to be a judgment
call the first version of the rule got slightly wrong — a real
generated example showed the stricter reading removed something
genuinely useful, so the rule is relaxed based on that evidence rather
than on speculation. The severity-filtering gap didn't show evidence of
a bad rule, just a model not fully complying — so that rule stays as
strict as originally written.
