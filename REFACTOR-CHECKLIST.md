## Refactor and migration safeguards

- **Project-independent semantics:** Harscode reusable guidance cannot rely on a named target project's product/domain/implementation facts, brand, repository slug or source history.
- **Authority before location:** A branch, move or new README does not promote a historical approval; check owning sources and exact approved revisions.
- **Selective migration:** Preserve meaningful safeguards and consumer contracts; avoid automatic bulk-copying prior prose or building a mandatory new workflow/process.
- **Evidence before readiness:** Independent real consumer work, actual runtime, permissions, and integration claims remain separate checks; do not infer them from source-level audit or polished documents.
- **Immutable original:** The dated migration phase history, resolved project-specific source traces and Human decisions remain available at the exact historical Git revision linked above.
