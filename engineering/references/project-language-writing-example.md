# Project Language and Writing Profile — Reusable Reference Example

> **Standing:** Optional, non-binding Harscode reference library entry, **not** Harscode configuration, operational language policy or a Kencleng approval. A target project must own and approve its effective language/terminology conventions. This is a model for project-specific drafting, not a requirement to create a separate profile file.

## A project may adopt rules such as

1. Use the project's chosen primary language for human-facing explanation; prefer familiar, direct words. Preserve official names and technical identifiers where translation loses precision.
2. Prefer short sentences and actionable rules over repeated narrative. Context exists to clarify decisions and consequences.
3. Define checkable criteria when terms such as *valid*, *sufficient*, *approved*, or *relevant* determine acceptance or authority.
4. Separate observed facts, accepted decisions, proposals, uncertainty and executed versus NOT RUN evidence; never translate away the distinction.
5. Respect concern authority: Product specifies outcomes and constraints, Engineering selects mechanisms; editorial wording cannot invent either.
6. Keep API paths, field names, types, status codes and other machine-readable identifiers exact. Follow current owning project specification conventions.

## Conditional bilingual Product artifacts

- Create both Indonesian and English versions **only when justified by real consumers**; no universal bilingual deliverable requirement.
- The target project explicitly selects the authoritative language/version. Any other language is a labeled translation, not an independently editable policy.
- Preserve modality (*must/shall/should/may* versus *wajib/sebaiknya/boleh*), exceptions, scope, ownership, decision status and acceptance criteria. Reconcile translations against the effective original after substantive changes.
- Do not replace project-specific terminology rules with this example. Avoid blanket rewrites of historical documents.

## Application by Rancang

Discover applicable effective target-project language and writing rules, if material. Use them for narrative artifacts and Human-facing handoffs, without changing technical identifiers, project authority or the Space's Engineering Solution mission. An absent profile file alone is **not** an input blocker. Missing material terminology authority should be surfaced only when it would change substantive meaning.
