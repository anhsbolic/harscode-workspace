# Engineering Project Standards — Agent Guidance

> **Standing:** A4 direct research concern / HUMAN CONTENT REVIEW PENDING. This file authorizes neither an Engineering Space invocation nor an actual project write.

## Required behavior

1. Identify exact target project, effective branch/revision and what cross-feature Engineering decision is at stake. Inspect owning originals and applicable project-specific policies; do not use remembered discussion as authority.
2. First test `REUSE / NO CHANGE` or a permitted **feature-specific Engineering decision**. An absent formal standards catalog is not proof of a missing material standard.
3. Demand concrete repeated need **or justified current/committed cross-feature applicability**, actual impacted consumers, security/privacy implications and the smallest rule that solves the need. Future hypothetical reuse alone does not suffice.
4. Separate proposed standards, effective accepted standards, current technical evidence and historical precedent. Never promote a Rancang handoff, code implementation, Agent preference or example into canonical project policy by naming it a standard.
5. Obtain source-independent security review where protection/trust/privilege consequences require it. A project or Architect cost preference cannot silently lower binding safeguards.
6. Before consequential change, identify real owner, exact text/revision to accept, affected consumers, compatibility/migration/reversal, required Human approval and write/permission boundary. Actual tool access is not authorization.
7. Persist only narrowly authorized target-project changes. Reopen effective sources, reconcile stale current references, identify still-OPEN decisions, and report checks actually performed versus NOT CHECKED.
8. Report a precise owning decision/blocker to Human when authority remains missing; unrelated valid work can continue.

## Hard exclusions

No design of feature API/schema as a substitute for Rancang; no Product meaning, UX/web routes, UI decisions, code implementation, deployment, global Engineering standards registry, automatic Space invocation, permission escalation or blanket security-risk acceptance.

Project standards **inform** Rancang and Builder; this concern does not dispatch or approve either.
