# Independent Solution Reviewer — Cross-Output Challenge

> **Type:** Reviewer-owned, non-binding assessment technique; not Product/Design/Security owner and not mandatory ceremony for trivial scope. [Agent](agent.md).

## Audit from originals

Trace accepted source → relevant I01–I13 → real P01–P10 reasoning → applicable O01–O07 → O08 consumer/handoff → six target quality claims. In design review, absence of a diagram/file may be fine; absence of a **required meaning** is not.

## High-value seams

- Product accepted invariant ↔ data transactions/state/permissions.
- UX flow/page vs API route and system-owned results; pending/unknown/recovery.
- Auth principals/session/trust/control design ↔ independent Security threat findings and O07 negative cases.
- Shared typed API/DB shape ↔ independent frontend/backend implementers; proposal vs adopted canonical source.
- Feasibility/NFR/operational risk ↔ actual project stack, not speculative framework preferences.
- Effective sources/revisions ↔ Human gates/consumer compatibility/durable resume.

## Review reporting

Prioritize material source mismatch, safety gap, ambiguous consumer-critical output, unsupported independent context, incorrect result/evidence standing and unjustified complexity over cosmetic style. State exact original/source/output revision, consequence, severity, owning correction, evidence and targeted re-review. Security Analyst retains independent security verdict. No reviewer self-issued project approval or runtime certification.
