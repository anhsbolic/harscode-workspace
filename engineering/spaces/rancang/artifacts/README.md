# Rancang — Artifact Representation & Consumer Use

> **Standing:** Optional non-binding research formation-candidate aid. The [external contract](../contracts.md) governs eight logical outputs, not a prescribed file layout.

## Minimum usable representation

Follow the **actual target project's effective** engineering/technical documentation, API/data formats, language and security standards. One owned artifact may contain several logical outputs; a consumer-required typed O03 interface needs a complete deterministic proposed contract, not scattered prose. Rancang does not edit/adopt the project's canonical feature API/schema by default.

A material result must be attributable: exact owning source and acceptance scope, accountable Architect section/content revision, reasoned design decision and constraints, actual known consumer, linked security/UX/reviewer findings, planned O07 cases versus observed results and remaining Human gates. A manifest of hashes alone is not an implementation-consumable solution.

For **full output authoring**, use the optional [Rancang Output & Consumer Handoff template (Bahasa Indonesia)](../templates/rancang-output.id.md) or [English](../templates/rancang-output.en.md). These provide concrete source, I01–I13, O01–O08, evidence and consumer-readiness tables comparable to Product/UX/UI research authoring guides. The shorter [eight-output prompts](templates.md) are a quick sufficiency reference, **not** an alternative binding contract. Neither format forces eight files, an API technology, a second canonical Product/UX source or reviewer self-approval.

## Effective handoff

Coordinator points to **one effective, project-owned recoverable O08 package** with O01–O07 contents, separately authored independent review/security findings, Human acceptance status and consumer-specific restrictions. Do not require implementers to stitch incompatible prior drafts; historical Git checkpoints are still discoverable. Administrative repackaging after accepted substantive bytes must distinguish the accepted identity from new packaging.

Report `NOT APPLICABLE` only where meaningful; `NOT CHECKED/UNVERIFIED` if original/consumer/runtime evidence was absent. Keep temporary scripts, screenshots or test artifacts only where actual consumer/replay/security evidence justifies retaining them; never delete needed original authority or pretend missing artifacts were archived.
