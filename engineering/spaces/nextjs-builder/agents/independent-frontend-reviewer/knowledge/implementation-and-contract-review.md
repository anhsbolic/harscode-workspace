# Independent Review of Next.js Implementation and Experience Contracts

> **Applicable when:** source, frontend UI or API consumption has material behavior to challenge. This is not a checklist to run every test suite or redesign accepted Product/Design decisions.

## Read originals and ask what would falsify the claim

Independently locate the current bounded objective, effective Product/Design/Engineering/security/API meaning, explicit API mode, project SOP, allowed paths and exact code change. Producer summary is an index, not authority. Identify the highest-value mismatch candidates: contradictory user result, inaccessible action, stale private cache, wrong session actor, material visual drift, unauthorized brand asset, or a real provider mismatch disguised by mocks.

Trace two directions: accepted obligation → actual implementation → observed evidence; and implemented behavior → binding source or ordinary delegated discretion. Differentiate useful improvements from required defects. Do not invent “must have a sitemap”, “must use my preferred state store”, “every component gets Playwright” or a generic aesthetic as a blocking standard.

## Implementation seams

Challenge framework-version-specific routing/rendering/cache claims, server-only data exposure to browser, URL/identity state, query invalidation, form/backend validation ownership, and handling of failed/denied/partial/unknown mutation results. Assess actual mode: mock mode can prove faithful frontend handling only; real mode requires evidence from real provider. Backend defect ownership remains external; when material backend blocker prevents integration, Reviewer supports a STOP/BLOCKED finding, not mock fallback.

## UI and Craft seams

Compare relevant observed UI states against accepted hierarchy, responsive meaning, visual/asset rules and accessibility. Ensure copy/icons/verification badges do not promise outcomes that cannot be confirmed. Distinguish measurable defects (clipped action, absent label, false success, wrong logo) from ungrounded taste. Craft Specialist findings are production feedback—not independent review and not automatically correct.

## Findings and recheck

Each finding must identify source and output revision, observation/reproduction, severity and consequence, owning producer/authority, affected consumer, correction and targeted recheck. Do not edit Engineer-owned code as a reviewer or self-approve your own fix. When code/contract changes, invalidate only affected findings and evidence; do not reopen settled design for preference.
