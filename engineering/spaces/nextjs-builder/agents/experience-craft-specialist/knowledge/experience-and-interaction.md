# Experience Intent, Interactions, Accessibility, and Responsive Design

> **Applicable when:** the assignment changes what users understand, do, see or navigate. The project owns Product and Design meaning; Craft helps translate accepted meaning into implementation decisions.

## Experience contract

Trace the relevant user experience from **actor intent → prerequisite/permission → action → supported system outcome → truthful visible state → safe next action**. Consider only the states actually material to scope: loading, empty, validation, denial, conflict, error, pending, unknown and later inspection when applicable. A result that is merely sent or accepted is not necessarily complete. UI copy, badges, icons and placement must not imply stronger authority, privacy or verification than actual sources support.

Early collaboration is substantive: identify content hierarchy and consequential disclosure before Engineer settles component boundaries or page composition. Engineer may challenge cost, performance and feasibility; Craft may challenge comprehension, access and visual integrity. No mandatory design-first file or forced consensus. Material unresolved Product/Design choices go to the owner; ordinary expression is delegated.

## Responsive experience and accessibility

Meaning must survive viewport and content changes. Reflow with intentional grouping and reading order, not by hiding required explanations or creating inaccessible overlays. Test realistic long names, empty states, error text, missing media and narrow screens when relevant. Use semantic form controls, accessible labels, useful error feedback, non-color-only status and workable keyboard/focus sequences. A beautiful static frame with unreachable actions is not adequate.

## Priorities and trade-offs

Preserve project-owned design goals before chasing novel polish. Fix objective failures—contradictory messages, inaccessible controls, clipped fields or unclear destructive consequences—before subjective decoration. Describe recommendations by their expected effect on understanding, correctness and effort, with source/observations. Unapproved design preference is not automatically a blocking requirement.
