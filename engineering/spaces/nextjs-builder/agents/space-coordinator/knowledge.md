# Coordinator — Authority, Sufficiency, and Mode Decision Knowledge

> Agent-owned operating guidance; the [external contract](../../contracts.md) and [coordination rules](../../coordination.md) remain binding for this Space. Target project authorities and Human permissions determine the actual assignment. Load this only when coordinating or resuming an assignment.

## Resolve work without inventing policy

Start from the Human's project/work identifier, find the current project-owned source, current code/branch, relevant Design and Engineering standards, and specific accepted decisions. Distinguish *effective*, *proposed*, *historical*, and *observed* evidence. A branch or commit identifies a source snapshot, not automatically approved Product meaning. Do not require a prescribed file format or a Rancang handoff for a task whose observable objective is already sufficiently authoritative.

For a missing input, identify its **affected action**, why it is material, and its owning authority. A missing optional document, sitemap, design token or backend runtime is not automatically a reason to refuse independent authorized work. Conversely, no amount of Engineering discretion authorizes a new grant, money effect, privacy disclosure, canonical brand identity or shared API outcome without source authority.

## Select mode and enforce authority

For an API-dependent objective, bind `MOCK_DEVELOPMENT` unless the Human expressly requested `REAL_API_INTEGRATION`. Mode is part of the exact assignment, not an automatic response to backend availability. For API-independent work, record N/A without creating mocks. Resolve effective project SOP first, including manual-only testing requirements and explicitly forbidden operations. Confirm the actual allowed read/write/tool/commit/service/test/asset boundaries, not just what credentials happen to permit.

When a later real-integration assignment starts, require exact frontend and backend/source contract identities and a reachable, permitted target environment. Distinguish provider's “ready” claim from consumer observation. On material backend blocker, ask Engineer for bounded attribution and return a `BLOCKED` handoff; never authorize mock fallback implicitly, nor preserve a session waiting for an asynchronous backend repair.

## Durable evidence and joins

An accountable producer owns code or findings; Coordinator assembles pointers and standing, not substitute conclusions. For each output check the correct revision, current approver, evidence owner, actual method/provider, outstanding required action, and consumer. Keep project-owned reconstructable state so a fresh session locates the source/output with only authorized work identity. No global registry or new scheduler is needed.
